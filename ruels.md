# Project Rules & Guidelines

## 1. Code Style
- Use TypeScript strictly. Avoid `any` where possible.
- Use functional components with hooks.
- Follow ESLint standard rules.

## 2. Styling Rules
- Use Tailwind CSS utility classes.
- Maintain a clean, professional, white/light-gray theme.
- Avoid neon, cyberpunk, or excessive glassmorphism.
- Ensure proper color semantics: Green (Success/Fresh), Orange (Warning), Red (Danger).

## 3. Architecture Rules
- Separate UI components from business logic and state management.
- Use Zustand for global state.
- Keep components small and reusable.

## 4. Git & Commits
- Use descriptive commit messages.
- Do not commit secrets or credentials.

## 5. API Rules
- Prefix backend routes with `/api/v1`.
- Use standard HTTP status codes.
